# 前端交互设计

## 表单布局与控件

- 桌面端可以把表单居中放在面板内，按字段内容设置最大宽度。标签靠近控件，窄窗口改为上下排列。数字框可以比文本框短，宽度由内容决定。
- 长表单只滚动字段区。滚动容器铺到面板边缘，字段内容在容器内居中，避免滚动条紧贴输入框。「运行」「重置」和快捷键放在滚动区下方，与控件列共用对齐线。没有字段时，提示和操作区共用一条居中轴线。
- 枚举下拉框复用 `AppSelect`，可选字段可以通过「未设置」恢复留空。文本框有值时可在框内显示清空图标，并提供可访问名称。数字框和多行编辑器可直接删空，复选框沿用勾选交互。表单需要区分未填写、空字符串或显式 `null` 时，按参数约定分别处理。

## 校验与运行反馈

- 格式错误和必填提示显示在对应控件旁。桌面端空间足够时放在右侧，空间紧张时放在下方。按校验时机显示提示，避免尚未交互的表单出现大面积错误态。
- 连接失败等运行错误通过 `showError` 在窗口顶部显示详细原因。卡片仅展示「连接失败」等简短状态，保持列表布局稳定。

## 切换动效与文本显示

- 表单和 JSON 双向切换时保留已填的值。根据 Schema 初始化时，使用已声明的默认值；当前输入无法完整转换时，保留原内容并提示。切换内容可用轻微位移，选中高亮复用 `src/utils/motion.ts`，避免内容闪烁、回弹和文字缩放。
- 可关闭的弹出面板复用 `src/styles/motion.css` 的动效，从上方滑入并淡入，关闭时上移并淡出。普通浮层支持点击外部收起。动效遵循系统「减少动态效果」设置。
- JSON 输入可根据宽度软换行，保持编辑内容原样。格式化结果保留格式化产生的换行，原始响应和日志保留各自的行边界。查看长行时可以横向滚动。
